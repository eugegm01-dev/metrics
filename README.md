# go-musthave-metrics-tpl

Шаблон репозитория для трека «Сервер сбора метрик и алертинга».

## Начало работы

1. Склонируйте репозиторий в любую подходящую директорию на вашем компьютере.
2. В корне репозитория выполните команду `go mod init <name>` (где `<name>` — адрес вашего репозитория на GitHub без префикса `https://`) для создания модуля.

## Обновление шаблона

Чтобы иметь возможность получать обновления автотестов и других частей шаблона, выполните команду:

```
git remote add -m v2 template https://github.com/Yandex-Practicum/go-musthave-metrics-tpl.git
```

Для обновления кода автотестов выполните команду:

```
git fetch template && git checkout template/v2 .github
```

Затем добавьте полученные изменения в свой репозиторий.

## Запуск автотестов

Для успешного запуска автотестов называйте ветки `iter<number>`, где `<number>` — порядковый номер инкремента. Например, в ветке с названием `iter4` запустятся автотесты для инкрементов с первого по четвёртый.

При мёрже ветки с инкрементом в основную ветку `main` будут запускаться все автотесты.

Подробнее про локальный и автоматический запуск читайте в [README автотестов](https://github.com/Yandex-Practicum/go-autotests).

## Оптимизация производительности

В ходе выполнения 19-го инкремента были проведены следующие оптимизации:

- **Пул воркеров в агенте** – сбор метрик и отправка разнесены по горутинам, что позволило снизить задержки и увеличить пропускную способность.
- **Пакетная отправка метрик** – агент отправляет метрики батчами, уменьшая количество HTTP-запросов.
- **Использование sync.Pool для gzip-буферов** – снизило аллокации памяти.
- **Ретраи для HTTP-запросов** – добавлены повторные попытки при временных ошибках (как в агенте, так и в HTTPObserver аудита).
- **Критические секции сокращены** – в файловом аудите маршалинг вынесен за мьютекс, что уменьшило время блокировки.
- **Защита от двойного закрытия файлов** – в `FileObserver.Close()` добавлена проверка на nil.

Результаты бенчмарков (до/после) можно увидеть в `profiles/`.

## gRPC‑интеграция

Сервер может принимать метрики по gRPC. Для этого агенту и серверу необходимо указать адрес gRPC-эндпоинта.

### Запуск с gRPC

**Сервер:**
```bash
go run cmd/server/main.go \
  -a :8080 \                 # HTTP-адрес
  -g :50051 \                 # gRPC-адрес
  -t 192.168.1.0/24 \         # доверенная подсеть (CIDR)
  -d postgres://...           # DSN базы данных (опционально)
